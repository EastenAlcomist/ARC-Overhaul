# ARC Overhaul changes

[中文](CHANGELOG.zh-CN.md)

## Unreleased

- Add **AI fleet control**: a new *ARC Overhaul: AI fleets* screen (conquest setup → bottom of the settings list, or MOD list → ARC Overhaul → Details) lists every AI fleet the game has loaded and gives each one three states — **Allow** (may be picked at random, vanilla), **Force enable** (reserved and handed to exactly N non-player countries) and **Force disable** (never used). An AI fleet is one `ConstructionStrategy`: it decides which ships, landships, buildings and techs an empire uses. The native game picks one per empire with `ConstructionStrategy.forCharge(charge, difficulty)` + `r.nextInt(size)`, filtered only by heraldic charge and difficulty, with no player control at all. ARC now chooses that fleet itself at the exact call site inside `WorldMap$2.run`, before the `Empire` is constructed — the hook has to be there because `Empire.constructionStrategy` is `public final` and cannot be replaced later. Rule semantics: a force-enabled fleet is removed from the random pool as well, so "3" really means exactly three countries; a banned fleet never appears; the player's own country is never replaced; if every candidate ends up banned or reserved ARC keeps the vanilla pick instead of failing generation. With default settings the method returns before touching anything, so no random draw is consumed and a given seed still produces the vanilla world. Settings live in `game/config/arc_overhaul/conquest-fleets.json` and only non-default entries are written.
- Add **Force disable all** and **Force enable all** buttons to the AI fleet screen: one click marks every loaded fleet, and "force enable all" keeps each fleet's current country count (or its last valid one) instead of resetting it. Each fleet row also reports where the fleet came from in its tooltip (the game's own data, or the name of the fleet pack's folder).- Make the country-count box usable. It previously snapped back to its old value the moment you cleared it, because it was bound to a value that never allowed an empty string — so changing 1 to 3 meant fighting the field. The box now shows exactly what you typed, including empty, and an empty box is neither an error nor saved as 0: it keeps the last valid number. The error line under the box only appears for something you really typed wrong. The box is also nudged down by a small spacer so it lines up with the buttons beside it instead of sitting at the top of the row. It cannot be painted grey while inactive — see the framework gap below.- Two of the requested ergonomics still need Acbric changes and are **not** done here. (1) The count box looks identical whether or not it can be typed into, because the framework canvas adapter (NativeUiCanvas.text) ignores its enabled flag when painting glyphs, and it deliberately escapes square brackets so a MOD cannot inject the game's rich-text colour codes; painting inactive text grey is a one-line framework change. (2) Restoring the deleted number when you click into another box without typing needs a focus-lost notification, and UiRuntime currently changes focus with no callback. ARC instead restores empty boxes on the next thing you do — typing in any other box, pressing any button, or Apply — and never writes a 0. Before touching the framework, note that its source tree is at 0.3.3-dev.33 while the built and installed API jar is 0.3.3-dev.21, so a rebuild would also land dev.22-dev.33 in the game.
- ARC's shared-rule declaration now carries both the starting values and the fleet rules in one JSON object, because the framework allows one declaration per MOD ID. The rule version stays 1 and a payload without the `fleets` key reads as "all allowed", so campaigns saved before this change keep loading.
- Validation for this change: game 1.2.15.2, **506 checks pass** with API `0.3.3-dev.21` (the previous 426 plus 80 fleet assertions). The hook target is asserted by parsing the shipped `WorldMap$2` bytecode: `run` has four `ArrayList.get` call sites and the one whose result is cast to `ConstructionStrategy` is call site #1, which is what `ordinal = 1` selects. Only one game build was available on this machine, so 1.2.14 was not re-run. See [TESTING](TESTING.md) for what is *not* covered. The MOD version is now `0.1.0-dev.5`; validated JAR SHA256: `151ce2348349b4e0d40976ea492c2ce8ae3a3a28d560f620202a5a46595eaa02` (rebuilding may change ZIP metadata and the hash).
- Fix extra starting towns losing their territory colour on the strategic map. Skipping unused placement slots left gaps in the native settlement ID sequence, and the native territory tracer (`ShapeUtils.cityOwnershipAreas`) walks IDs upwards from 0 and exits permanently at the first ID with no owning cell — so every settlement above that gap never received a territory area and was never painted. Settlement IDs are now assigned contiguously as they are created. When no placement slot is skipped the sequence is identical to vanilla, so maps using the default counts are unaffected.
- Add a **Player starting research points** field (0–10,000,000, default 0 = vanilla) to the ARC starting options. The value is banked into the native *unassigned* research pool (`Empire.unassignedResearchPoints`), which the game pours into the first research the player selects. Granting it through `Empire.researchPoints` does not work: the native set-research command (`CampaignWorld`, bytecode 223–312) overwrites that field with the new tech's partial progress before adding the pool, so the grant was silently discarded on the first click. The range is in the millions because a technology costs `BASE_RESEARCH_COST × RESEARCH_COST_MULTIPLIER × 5600 × 1.4^tier` points (`Tech.baseCost`) — measured in-engine as 1,680,000–2,352,000 for the first tiers; a smaller grant is invisible on the progress bar. The probe asserts the range stays within scale of a real technology. Grantee timing is identical to the existing cash grant (same CREATED callback, same loop) and the grant is logged.
- Keep ARC-added settlements off isolated land. The native spot finder `WorldMap.findMapLocationSpot` only requires the candidate tile to be *not water*, so a single land tile surrounded by sea is a valid result and an added town could be generated on a speck connected to nothing. ARC now wraps that call for human empires and re-rolls until the tile belongs to a connected landmass of at least `max(32, gridSize/4)` tiles; the retry budget is bounded and falls back to the last candidate, so the guard cannot turn generation into a failure. AI empires and default settings keep the untouched native result. Verified with an A/B probe: the unguarded native finder places a settlement on an isolated island for 6 of 16 seeds, and with the guard the same seed lands on real land.
- Validation for this change: game 1.2.15.2, **426 checks pass** with API `0.3.3-dev.21` (the 407 colour-fix checks plus the research, land-guard and scale assertions). Test game 1.2.14 and API dev.25 were not re-run here.
- PR #1 was initially validated using a standalone copy of the native tracer. After merging, add contiguous-ID, city-cache and native territory-tracing regressions: 407 checks each for game 1.2.15.2 / 1.2.14, 814 total, with API `0.3.3-dev.25`. The old dev.3 JAR fails the new assertion as expected. The user confirmed the fix in manual gameplay testing. See [TESTING](TESTING.md) for fixtures, synthetic ownership grids and coverage limits; this does not establish full multiplayer acceptance.
- Report landship speed with its **ground friction**. The native panel speed (`ShipEditorUtils.getStats` → `Airship.getMainMapSpeed` → `getSpeed`) subtracts only quadratic air drag, but every grounded spring also damps horizontal speed by `(1 - Spring.xFriction × fMult)` **per tick** (`Module.java:679-684` for tracks, `Leg.java:299-304` for legs; `ModuleType` hard-codes 0.002 for module springs and 0.004 for leg springs). Airships have no springs, which is why only landship numbers were wrong. ARC now solves the real steady state `F/m = f·v² + λ·v` over air friction plus ground friction and reports that value, so the editor, strategic screen and combat panel all show the speed the ship actually reaches. Measured in headless combat (flat ground, full throttle, direct control, no terrain contact): a Medium-Legs walker reaches 0.235 against the 0.690 the old panel claimed (34 %), Large-Tracks 27 %, Tracks 16 %, while a springless airship keeps the native value. Gameplay is untouched: AI, strategic-map movement and the `engineForceForX` braking simulation still use the native formula.
- Validation for the ground-friction report: game 1.2.15.2, **438 checks pass** with API `0.3.3-dev.21` (the 426 existing checks plus 12 new ones: real mixin transformation on `ShipEditorUtils`, the native per-tick decay rule, the λ solve, spring collection for landships versus airships, and the panel value being strictly lower). Test game 1.2.14 was not re-run here.
